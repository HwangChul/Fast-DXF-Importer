# Fast DXF Importer

面向数十 MB 图纸的 Blender DXF 导入器：numpy 向量化解析 + 单 mesh 合并，
25 MB 图纸约 3.5 秒、200 多万顶点。

相对上一版补了三件事：

| 改动 | 说明 |
|---|---|
| **镜像块修复** | 处理 DXF 的挤出方向（210/220/230，OCS）。此前只做平移+旋转+缩放，法向为 `(0,0,-1)` 的块会整个翻到反方向 |
| **文字导入** | `TEXT` / `MTEXT` / `ATTRIB` 描成**字形轮廓折线**并入同一网格，中文正常显示 |
| **线框转实体面** | 每条边扩成极细的四边形带，导出 OBJ 后是真正的面，供 Isaac Sim 这类只认面的引擎使用 |

## 安装

Blender 4.2+：`编辑 > 偏好设置 > 扩展` → 右上角下拉 → `从磁盘安装` → 选 `fast_dxf-0.2.0.zip`。

安装后菜单在 `文件 > 导入 > Fast DXF (.dxf)`。

## 参数

**单位**

- `自动单位`：读 DXF 的 `$INSUNITS` 换算到米（毫米图自动 ×0.001）。
  这个字段由出图软件填写，**经常是错的**，尺寸明显离谱时关掉它手动填缩放。
- `缩放`：`缩放 = 你想让模型多大（米） ÷ 图纸单位数`。某张卡车模型图宽 31115 单位，按毫米填 `0.001`。
- `居中到原点`：大坐标图纸（如测量坐标 4,000,000 级）建议打开，避免 float32 精度损失。

**几何**

- `圆弧细分`（默认 64）：整圆分多少段。越小越快。
- `样条细分`（默认 12）：每条样条的采样点密度。
- `多段线圆弧`：把 `LWPOLYLINE` 的 bulge 段还原成圆弧。
- `展开块引用`：展开 INSERT，阵列一并展开。
- `无引用块按块库导入`：`ENTITIES` 里没有线框时，把 `BLOCKS` 里的块定义按网格铺开。

**文字**

- `导入文字`（默认开）：关掉可省时间（几千条文字会明显变慢）。
- `字形精度`（默认 6）：字形轮廓的细分密度。
- `字体`：留空自动找一个中英文都有的字体（思源黑体 / 文泉驿 / 微软雅黑 / 苹方）。

**导出兼容**

- `线框转为实体面`：见下文。
- `线宽`：转面时的带宽，图纸单位；`0` 表示按图纸实际跨度自动估算。

## 坑一：镜像块（本版修复）

DXF 里有一类实体，坐标不是世界坐标，而是画在它自己的**对象坐标系（OCS）**里：
点 `(x, y, z)` 的含义是 `x·Ax + y·Ay + z·Az`，`Az` 就是组码 210/220/230 给出的
挤出方向，`Ax/Ay` 由 AutoCAD 的「任意轴算法」推出来。

当法向是 `(0,0,-1)` 时这套基是翻转的，同一个 `(x, y)` 落到世界坐标就被镜像了。
旧代码只做平移+旋转+缩放，于是**镜像放置的块整体跑到图纸的另一侧**——
表现就是"这个块应该在右边，却出现在左边"。

实测某办公楼施工图（28.7 MB）：顶层 108 个块引用里有 **14 个带镜像**，块定义内部还有 27 个。
受影响的实体类型：`INSERT`、`LWPOLYLINE`、`POLYLINE`、`ARC`、`CIRCLE`、
`ELLIPSE`、`TEXT`、`MTEXT`、`ATTRIB`、`HATCH`。

> `LINE` 和 `SPLINE` 的坐标本来就是世界坐标，不需要变换。
> `ELLIPSE` 是个例外：它的中心点和长轴是 **WCS**，法向只决定短轴方向——
> 按 OCS 整体变换反而是错的。

## 坑二：文字不是文字对象

导入的文字是**字形轮廓折线**，和几何进同一个网格，不是可编辑的 Text 对象。

选这条路的理由：一个 900 条文字、200 万顶点的图纸，如果需要"每条文字一个对象"，
outliner 和视口都会明显变慢，而且文字被旋转、被块缩放、被镜像时，
对象层级会变得很难维护。折线版在该图上验证过：文字位置与 ezdxf 逐条零误差。

代价：**改不了字**。要改文字就回 CAD 改。

细节处理：

| 项 | 处理 |
|---|---|
| 中文编码 | UTF-8 / GBK / Big5 依次尝试，老图纸不再变乱码 |
| MTEXT 格式码 | `\P` 转行、`\S1^2;` 转 `1/2`、`\U+00B0` 转字符，其余 `\f \H \C \W` 整段剥掉 |
| DXF 符号 | `%%c` 直径 `⌀`、`%%d` 度 `°`、`%%p` 正负 `±`、`%%%` 百分号、`%%u/%%o` 去掉 |
| 字高 | DXF 的组码 40 是"大写字高"，Blender 的 size 是 em。不同字体比例差一倍（思源 0.26、文鼎 0.69），**实测反推** |
| 宽度因子 | `TEXT` 的 41 是宽度因子；`MTEXT` 的 41 是**参考矩形宽度**（图形单位），两者不能混用 |
| 行距 | `MTEXT` 组码 44 的行距系数 × 5/3 × 字高 |
| 块属性 | 模型空间里跟在 `INSERT` 后面的 `ATTRIB` 坐标是块坐标，要再乘一次 insert 矩阵 |
| 行数上限 | 40000 条，超出的丢弃并在控制台报数量 |

> 不要用 **Droid Sans Fallback**：它是纯 CJK 回退字体，没有拉丁字形，英文会画成一片空心方框。
> 自动挑选会跳过文件名带 `Fallback` 的字体。

## 坑三：导出到 Isaac Sim 什么都看不到

插件导入的是**纯线框**（0 个面，只有边）。Blender 导出 OBJ 时只能把边写成 `l` 线段，
而 **Isaac Sim / Omniverse 的 OBJ 导入器只构建多边形面，会直接丢掉线段**。
症状：Blender 里看得见，导进仿真什么都没有。

打开 `线框转为实体面` 后：

- 每条边扩成一条很细的四边形带，OBJ 里变成真正的 `f` 面；
- 线宽填 `0` 时按图纸实际跨度自动估算，用 1%~99% 分位数排除远处的游离图块
  （有的图纸散落着极远的零散块，min/max 会被带偏到 8000 多米）；
- 代价：顶点数 ×4、面数 = 线段数。2 百万条边大约产生 8 百万顶点。

## 支持与不支持

支持：`LINE`、`LWPOLYLINE`（含 bulge 圆弧）、老式 `POLYLINE`/`VERTEX`（2D/3D）、
`ARC`、`CIRCLE`、`ELLIPSE`、`SPLINE`、`INSERT`（含阵列、嵌套、镜像）、
`HATCH`（只导**边界**，不导填充图案）、`TEXT`、`MTEXT`、`ATTRIB`。

不支持（跳过并在控制台统计）：

- `SOLID` / `3DFACE` / `REGION` / `BODY`：实心填充和三维面域（`REGION` 的几何只在 ACIS 二进制里）
- `ATTDEF`：块定义里的属性**模板**（真正的值在 `ATTRIB` 里，已经导入了）
- `LEADER` / `MLEADER` / `DIMENSION`：引线标注、尺寸标注的匿名块不展开
- `POINT`、`IMAGE` / `UNDERLAY` / `WIPEOUT`、`ACAD_PROXY_ENTITY` / `ACAD_TABLE`
- polyface mesh / polygon mesh 多段线（标志位 64 / 16）

其他取舍：

- 顶点存进 mesh 时是 float32。坐标绝对值超过 ~10 万单位时开「居中到原点」。
- 不写材质、不建集合结构、不保留线型/线宽。
- `MTEXT` 不按参考宽度自动折行。
- 实体着色模式（Solid）下线框默认看不见，按 `Shift+Z` 切线框模式。

## 遇到"没有可导入的线框几何"

提示会把文件里的实际内容报出来，对照下表定位：

| 现象 | 真实原因 | 处理 |
|---|---|---|
| 提示"找不到 SECTION" | 组码带前导空格（`  0` / ` 10`），AutoCAD 的标准写法 | 自动回退到容错扫描（23 MB 多花 0.19 s） |
| 提示"二进制 DXF" | 存成了 Binary DXF | 让 CAD 另存 ASCII DXF |
| 提示"文件头是 DWG" | DWG 改了扩展名 | 导出真正的 DXF |
| 提示"ENTITIES 段是空的" | 块库文件，或模型空间被写成 `*Model_Space` 块 | 「无引用块按块库导入」会铺开全部块 |
| 只有 `ACAD_PROXY_ENTITY` | 来自 Civil3D / Architecture 的代理对象，几何是不透明二进制 | 在原软件里 `EXPLODE` 或另存低版本 |

## DWG 文件怎么办

DWG 是二进制格式，没有公开规范，不适合塞进导入器。先转 DXF：

- **AutoCAD / 中望 / 浩辰**：`另存为` → `DXF` → 版本选 `2013` 或更高（`ASCII`，不要二进制）。
- **LibreDWG**（免费命令行）：

  ```
  ./configure --disable-bindings --disable-shared --enable-static && make -j
  programs/dwg2dxf -o 图纸.dxf 图纸.dwg
  ```

  两个注意点：`/tmp` 小于约 1 GB 时给 `TMPDIR` 指个大分区，否则汇编阶段报「设备上没有空间」；
  缺 `autoconf`/`m4` 时用 `make AUTOCONF=true AUTOMAKE=true`。

转换会掉东西：一张图里若有 500 多个块都叫 `*U`（动态块匿名名），DXF 要求块名唯一，
写出来只剩一个，引用这些块的几何会大面积丢失；`REGION`、`ACAD_PROXY_ENTITY` 基本无法还原。
**转换只适合拿数据做核对，正式出图请让 CAD 自己导出 DXF。**

## 不用 Blender 也能体检

```
python tools/dxf_probe.py 图纸.dxf
```

零依赖（仅标准库），输出模型空间与块内的实体类型分布，标出不会导入的类型，
并统计文字数量、位置范围、内容样本、块内文字和文字样式表。24 MB 约 1.5 秒。

## 变更记录

**0.2.0**

- 修：**镜像块错位**。补上 OCS（210/220/230）变换，覆盖 INSERT、LWPOLYLINE、
  POLYLINE、ARC、CIRCLE、ELLIPSE、TEXT、MTEXT、ATTRIB、HATCH；块内嵌套的镜像同样生效。
  合成用例与 ezdxf 逐条对拍 10/10 通过；该图 655 条文字位置零误差。
- 修：**ELLIPSE 的坐标系**。中心点与长轴是 WCS，不再套 OCS 变换。
- 修：`LWPOLYLINE` 顶点过滤后 bulge 数组未同步截断，导致整批圆弧丢失。
- 新增：`TEXT` / `MTEXT` / `ATTRIB` 文字导入，描成字形轮廓并入同一网格，
  中英文混排、宽度因子、倾斜角、行距、对齐方式、块内文字全部支持。
- 新增：`线框转为实体面` + `线宽`（自动按 IQR/分位数估跨度），供 Isaac Sim 的 OBJ 导入。
- 新增：`导入文字` / `字形精度` / `字体` 三个参数。
- 新增：GBK / Big5 编码回退，老图纸中文不再乱码。

**0.1.2**

- 修：组码带前导空格（`  0` / ` 10`）的 DXF 完全读不到内容（段定位改为快路径 + 容错回退）。
- 修：UTF-16（带/不带 BOM）、UTF-8 BOM 的 DXF 能正常读。
- 新增：二进制 DXF、DWG 改扩展名时给出明确错误。
- 新增：`HATCH` 边界导入（多段线 / 直线 / 圆弧 / 椭圆 / 样条边界），
  含顺时针弧边的补角换算和边界路径末尾 `97`+`330/360` 句柄的跳过。
- 新增：块库回退（无 INSERT 引用时把块定义按网格铺开）。
- 修：块定义内部解析不再污染 `ENTITIES` 的实体统计。

**0.1.1**

- 修：块内最后一个实体的结束行被算到整个 `BLOCKS` 段末尾，导致坐标乱窜、满屏乱线。
- 新增：老式 `POLYLINE` / `VERTEX`（2D/3D/闭合/bulge）。
- 修：`bulge` 按顶点位置对齐，不再依赖 `42` 组码出现次数；3D 多段线不再被压平。
- 优化：样条 de Boor 求值改为向量化，25 MB 图纸几何阶段 11.2 s → 2.7 s。

## 目录结构

```
fast-dxf/
├── __init__.py          # 算子注册、参数面板、菜单
├── blender_manifest.toml
├── fx/
│   ├── dxf.py           # 词法、段定位、实体分组（不依赖 bpy）
│   ├── ocs.py           # OCS（挤出方向）到 WCS 的变换
│   ├── geom.py          # 实体 -> 顶点/边数组 + 文字收集（不依赖 bpy）
│   ├── text.py          # TEXT/MTEXT/ATTRIB 解析与格式码清理（不依赖 bpy）
│   ├── build.py         # 数组 -> mesh、字形描边、线框转面（依赖 bpy）
│   └── importer.py      # 编排与计时
├── tools/
│   └── dxf_probe.py     # 零依赖体检脚本
└── tests/
    ├── make_cases.py    # 生成用例与期望值（开发期用，需要 ezdxf）
    ├── test_import.py   # 测试本体（只需要 numpy）
    └── cases/           # 合成图纸 + 期望值 JSON
```

## 测试

```bash
python -m unittest discover -s tests -v
```

只依赖 **numpy**，不需要 Blender、不需要 ezdxf。测的是 `dxf.py` / `geom.py` / `ocs.py` / `text.py`
四个不依赖 `bpy` 的模块（`build.py` 要 bpy，不在测试范围内）。

用例是合成图纸，期望值由 ezdxf 独立算出并冻结在 `tests/cases/*.json`，所以跑测试时不用装 ezdxf。
要重新生成（改了实现、想加用例时）：

```bash
pip install ezdxf
python tests/make_cases.py
```

六个用例各自对应一个真实踩过的坑：组码带前导空格、块名含 `$` 与 `#`、
法向 `(0,0,-1)` 的镜像实体、TEXT 宽度因子与 MTEXT 参考宽度混用、
直线与 bulge 圆弧混排、嵌套块叠加缩放旋转。
